# Agent installation instructions

Use this when the user asks to install GitHub Year in Review. Complete installation and readiness checks; research starts from a separate user request. Treat the user's message and the host's permissions as authoritative.

1. Locate the source the user supplied: the repository URL, an attached ZIP, or a local checkout. Clone a repository or extract the ZIP into a temporary directory through the host's available tools. Inspect archive paths before extraction; reject entries that escape the destination. Find the directory containing this INSTALL.md, SKILL.md and scripts/install_skill.py. If no source was supplied or it is inaccessible, ask only for that missing source; do not invent a repository URL.
2. Identify the current harness from its actual runtime/session context. Use its existing configured user-level skills directory where supported; otherwise use its documented default. README.md lists example destinations. Honor an explicit user destination. Install for the current harness only. If skill discovery is unsupported, keep the files in an accessible persistent folder and explain manual invocation by reading SKILL.md. Ask about the destination only if the host genuinely cannot establish one.
3. Inspect scripts/install_skill.py before running it. Find an available Python 3.11+ interpreter. With ordinary user permissions, run `<python> <source>/scripts/install_skill.py --skills-dir <native-skills-directory>` using correctly quoted paths or structured process arguments. Default to a self-contained copy: a symlink into a temporary download will break when cleaned up. A live link is appropriate only for a persistent local checkout when the user wants that behavior. Follow the host's permission rules for dependencies; surface missing tools requiring user/admin action rather than requesting secrets or bypassing controls.
4. Preserve an existing installation. If it already points to this source or has identical distributable files, verify it and report it as installed. The helper refuses to overwrite another copy. A differing existing installation is an update decision: explain the difference and obtain update instructions unless the user already requested an update. Do not delete another skill to make this installation succeed.
5. Verify the destination contains SKILL.md, INSTALL.md, scripts/collect.py, scripts/research_mode.py, references/harnesses.md and assets/frontend/package.json. Use the installed interpreter to run the installed collector's `--preflight`; it checks Git, gh and GitHub authentication. Use the installed installer's `--help` to confirm that scripts run from their new location. Check Node.js 22.13+ and npm for presentation readiness. Installation can succeed with prerequisites still missing: distinguish that state clearly from “ready to run.” Do not install frontend dependencies into the retained skill template.
6. GitHub credentials belong to the user. If gh is missing, help them install it using the host's normal permitted workflow. If unauthenticated, tell them to run `gh auth login` or offer the host's supported interactive sign-in flow. Never ask them to paste a token, password or browser cookie. Do not perform a collection to test installation.
7. Report the actual installation path, verification result, any missing prerequisites, whether the harness needs a refresh/restart, and its native invocation syntax. Confirm the skill is usable only after the relevant checks pass; do not claim discovery by the harness unless it has actually refreshed/listed the skill. Keep a manually invoked fallback available when discovery is not supported.

Keep the installed copy when cleaning up temporary downloads. The helper copies only reusable skill files, excluding Git history, caches, installed dependencies and private run data. No additional agent client or model API key is required by the installer.
